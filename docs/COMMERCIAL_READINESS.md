# 상업화 준비 체크리스트

진행 상황을 세션이 바뀌어도 이어 가려고 만든 문서예요. 칸을 채울 때마다 이 파일을 함께 고쳐요.
표시: `[x]` 완료 · `[ ]` 할 일 · 👤 사용자가 할 일(콘솔·계약·신고·결정) · 🤖 Claude가 PR로 할 일
구분: **확인** = 코드·콘솔로 직접 본 것 · **추정** = 아직 확인 안 한 것(확인 방법을 같이 적음)

원칙
- 가격·요금제·랜딩 문구는 사용자가 정해요. Claude는 원가에 근거한 후보만 내요.
- 운영 데이터 삭제, DB 스키마 변경, 키 교체·폐기, 외부 콘솔 설정, 결제·요금 변경은 사용자 확인 뒤에 해요.
  SQL은 파일로 만들고 실행은 사용자가 Supabase 대시보드에서 해요.
- 법률 항목은 일반적인 요건을 정리한 것이에요. 최종 판단은 관할 기관(세무서·구청·방송통신위원회) 안내나 전문가 확인으로 해요.

## 1단계. 안전 — 출시 전 필수 (사고를 막는 일)

- [x] 🤖 **서버 로그인 확인 켜기(치명)** — Worker 입구에서 토큰 없는·틀린 요청 401(11-23). 관리·정리·알림 주소는 비밀값·자체 확인 유지.
  비상 스위치 `API_AUTH=off`
- [ ] 🤖 여행 멤버 확인 — 주소별로 "그 여행의 멤버인가"까지 확인
- [ ] 👤 Vercel 옛 주소 닫기 — `mongsil2.vercel.app/api/*`는 로그인 확인이 없어요(5단계 정리를 앞당기는 것을 권장)
- [ ] 👤 **Gemini 유료 등급 전환** — 무료 등급은 입력이 제품 개선에 쓰일 수 있고, 문서·여권 사진이 들어가요
- [ ] 👤 **Google Cloud 예산 알림 + API별 하루 할당량 상한** — 방법은 앞서 안내함. 설정했는지 확인 필요
- [x] 🤖 **오류 감지(코드)** — 앱 오류를 `client_errors`에 기록(30일 보관, 개인정보 가림), 다운 감시용 `/api/health`(11-23)
- [ ] 👤 `supabase/client_errors.sql` 실행 + 외부 업타임 감시(예: UptimeRobot 무료)에 `https://www.mongsil2.com/api/health` 등록
- [ ] 🤖 초대 코드 강화 — 지금 6자리·만료 없음 → 재발급·만료(DB 변경이라 SQL은 사용자 실행)
- [ ] 🤖 보안 헤더 — `public/_headers`에 CSP·클릭재킹 방지 등
- [ ] 🤖 외부 호출 타임아웃, 의존성 취약점 점검(`npm audit`)

## 2단계. 법·약관 — 출시 전 필수

- [ ] 👤 **운영 주체 결정** — 개인/개인사업자. 돈을 받기 시작하면 사업자등록이 필요해요(추정: 무료 운영 중엔 미룰 수 있음 → 세무서 확인)
- [ ] 👤🤖 **위치정보 관련 신고 여부 확인** — "어디야?"(일행에게 내 위치 전달)·주변 검색·도착 자동 기록이 위치정보를 다뤄요.
  위치정보법상 위치기반서비스사업 신고와 위치정보 이용약관 동의가 필요한지 **확인 필요(추정 단계)**.
  확인 방법: 방송통신위원회·위치정보지원센터 안내 확인. 필요하면 Claude가 약관·동의 화면 초안을 PR로 준비
- [ ] 👤🤖 **약관·방침 확정** — 사업자 정보, 위탁사 실제 국가(Supabase 리전 등 콘솔 확인), 로그 보관 기간 빈칸을 채우고 버전을 정식으로 올림
- [ ] 🤖 Google 장소 정보 보관 범위(Places 약관) 점검 — 저장하는 필드가 약관 안인지
